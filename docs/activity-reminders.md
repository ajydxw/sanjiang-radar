# 关注活动与日历提醒

首页和点赞页展示本机关注活动的未来报名时间。点赞后默认关注报名开始与截止；以前的私人收藏也保留作本机提醒，不自动公开点赞。打开活动详情可分别关闭提醒，设置存在当前浏览器。页面时钟每分钟更新，数据仍按原来的采集与刷新周期获取，名额不是实时状态。

在点赞页点击“导出日历提醒”，或在详情下载单条提醒，得到 `.ics` 文件。用支持 ICS 的手机日历导入并确认事件与提醒，允许日历发送通知。导入成功后的提示由手机日历负责，不需网页一直打开或电脑保持开机；手机端客户端是否保留文件中的提醒必须实际检查，不能承诺小米自带日历直接兼容。

- 已知具体开始时间：开始前 10 分钟及开始时提醒。
- 已知具体截止时间：截止前 24 小时、1 小时及截止时提醒。
- 只公布截止日期：保存真实全天日期标记，前一天与当天北京时间 09:00 检查提醒。09:00 是人为设置的查看提醒，不是推算的截止时刻。
- 未公布开始时刻、不合法日期、已过时间、满员、取消、明确不面向大一或来源已失效：不生成对应未来报名提醒。资格未知可保存，但提示核对官方资格。
- 已经过了的提醒点不补发。当天日期提醒已过时，仅导入日期标记并明确显示；时间紧时建议立即核对 PU。

这是一次性导入的公开信息快照。网站修改提醒、取消收藏、活动改期或取消不会更新手机日历。重新导入前核对并删除旧事件；即使 UID 相同，各客户端也可能产生重复事件。名额、报名成功与奖励不保证；及时发现信息与抢到名额是两件不同的事。

生成文件只包含活动公开信息，不包含学院资料、访客问题或私有凭据。采用标准 RFC 5545、UTC 具体时刻、全天日期与 DISPLAY VALARM，处理文本转义、UTF-8 行折叠和稳定 UID；未安装额外生产依赖。

## 开源参考与选型

| 参考 | 可借鉴之处 | 当前选型 |
| --- | --- | --- |
| [ics](https://github.com/adamgibbons/ics) | 生成事件、提醒与浏览器日历下载 | 学习接口与字段；本次仅生成固定提醒，使用小型本地实现 |
| [ical.js](https://github.com/kewisch/ical.js) | 标准日历解析、序列化与历法处理 | 复杂订阅或解析时再评估 |
| [ICSx⁵](https://github.com/bitfireAT/icsx5) | Android 的本地/远程日历导入和周期同步 | 手机不能直接导入时的可选开源客户端；未自动安装 |
| [ntfy](https://github.com/binwiederhier/ntfy) | HTTP 发布与手机通知 | 后续主动推送候选；需要客户端与可靠的任务调度 |
| [Novu](https://github.com/novuhq/novu) | 多渠道通知与工作流 | 当前约 10 人试用不引入整套通知服务 |

依据：[RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html)、[ntfy Android 投递说明](https://docs.ntfy.sh/subscribe/phone/)、[ICSx⁵ F-Droid 信息](https://f-droid.org/en/packages/at.bitfire.icsdroid/)。仓库资料用于参考，未复制或执行第三方安装脚本。

真正自动跟踪新活动、紧缺名额、改期并在锁屏送达，需要持续采集、可持久化订阅和可靠通知通道。本次按站长选择先提供免费日历方案，没有建立此类后台推送服务；还不能保证在网站尚未发现活动时发出提醒。
