# 共享点赞

卡片和详情用爱心点赞代替原收藏按钮，数字位于左侧。点亮时爱心从 0.8 放大到 1.2 再回到 1，使用回弹曲线；8 色圆点向外飞散淡出，数字向上滚动增加，动画 600ms。取消时恢复灰色。系统选择减少动态效果时保留最终状态，跳过装饰动画。

“点赞”导航保留原 `#saved` 地址，分为“大家点赞”和“我的点赞”。所有访客能看到被点赞的公开活动及总数，默认按赞数排序；首页也展示大家点赞的活动。每 15 秒更新可见页面，返回页面或点击刷新可立即读取。写入过程中先显示预期结果，网络失败会回退并提示核对，未确认的结果不冒充已完成。

## 私人与共享数据

- 旧 `sanjiang-radar-demo-v1` 收藏记录继续作为本机关注与日历提醒，并提供“本机原有关注”列表。旧记录不自动发送或计入公开点赞，避免把以前的私人行为直接公开。
- 新点赞由服务器持久化，每个匿名浏览器每活动最多一赞，可取消。公开接口只返回活动 ID、赞数，以及当前浏览器自己的点赞 ID，不显示其他点赞者。
- 使用随机 32 字节匿名凭据，Cookie 为 HttpOnly、SameSite Strict、限定 API 路径，公网启用 Secure；有效期 30 天。仅保存凭据的 SHA-256，不读取学院、专业、PU 账号或生活助手问题。
- 这是按浏览器计数，不是实名人数。清除 Cookie、换浏览器或更换临时域名可能改变匿名身份。Cookie 到期不会自动撤销以前的赞，基础限流不等于完整防刷。

## 接口与存储

`GET /api/likes` 返回 `{counts,likedIds}`；`PUT /api/likes/:id` 只接受 `{liked:boolean}`，按目标状态幂等写入。仅允许当前五份公开来源里的真实、非明确排除大一的信息 ID；撤下的活动不再展示计数。PUT 要求本站精确 Origin，正文最多 2KB，没有公开批量导入接口。

私有状态位于 `.sites-runtime/activity-likes/likes.json`，原子写入、跨进程写锁，有文件与目录边界验证。默认全局每分钟 300 次写、每匿名浏览器每分钟 30 次写；最多 10,000 个有赞访客、100,000 条赞和 16MB 文件。读取损坏会返回不可用，不自动清空或伪造零赞；进程崩溃遗留锁需停服核对后清理。

API 依赖现有 Node 后端，纯静态部署包不会包含点赞数据或接口；独立迁移时须一起迁移私有状态、写权限和服务。原有活动提醒、问答和管理员认证继续分别存储。
