# 上次来看之后新增

首页的「上次来看之后新增」显示新收集的信息数量，点击「查看新增」进入发现页的同名筛选。卡片显示「新收集」，原文发布日期仍单独保留；补收的历史通知不会被改成今天发布。

记录按信息编号和数据源保存在当前浏览器的 `sanjiang-radar-visits-v1` 中，只包含编号和访问时间，不保存文章全文或账号信息。首次访问、首次接通一个来源时，先记住已有信息；随后发现的新编号才计入新增。已知编号重新同步、临时移除后恢复时不重新计数，来源失败时保留其历史编号。

30 分钟内继续访问或刷新视为同一次浏览，新增标记保留。页面隐藏时停止随自动刷新更新访问记录，离开至少 30 分钟再回来会用上次访问的记录计算新增；返回页面时立即重新读取共享数据。它记录的是「访问之后新增」，并非逐条已读状态。

首页数量遵循大一资格和当前学院，次要宣传信息不计入。新增入口默认包含已截止的补收通知，避免因晚收集而完全隐藏；截止与资格仍需查看原通知。「发现」里的新增筛选可与其他筛选组合。

收藏和资料仍使用原来的存储键，新增记录不会覆盖它们。浏览器禁止保存、记录损坏或空间不足时安全降级，页面保留可用信息并提示。换设备、浏览器、网址或清除网站数据后，需要重新建立记录；尚无账号和跨设备同步。

参考：[Vercel React Best Practices](https://github.com/vercel-labs/agent-skills/tree/main/skills/react-best-practices) 中的浏览器存储版本与最小字段规则，保持现有依赖。代码遵循项目 Ponytail full 规则。

验证：`npm run test:visits` 覆盖首次访问、刷新、再次访问、重复同步、来源恢复、学院与年级筛选、旧原文补收、收藏保留、无法保存以及常用屏幕宽度；`npm run test:navigation` 检查底部导航原有交互。

当前电脑上已有静态网页服务和定时采集程序。这项功能无需增加完整后端；登录、跨设备同步、反馈或管理编辑需要时再补对应的接口和存储。电脑关机或断网时，增加后端也不会让网址继续在线。
